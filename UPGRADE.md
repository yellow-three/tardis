# Upgrading to 0.1

0.1.0 is the first (pre-release) version and the API may still change before 1.0. These notes are for anyone running an earlier development build of Tardis: 0.1 removes a set of APIs that were either unreachable, unused or unsafe, and every item below is a change from those builds. The commit history groups them by `!` commits.

## Before you upgrade

```bash
composer require yellow-three/tardis:^0.1
php artisan migrate
php artisan tardis:admin you@example.com   # authorization is on by default, see below
```

If you use `php artisan route:cache`, rebuild it after upgrading **and after creating a BREAD** (see "BREAD routes").

## Authorization is on by default

`TardisAuthorizationPlugin` is registered and enabled, and the admin middleware requires the `access admin` ability. A user with no role cannot open the panel. Run `tardis:admin` once. Set `tardis.authorization.enabled` to `false` only if you register your own `AuthorizationPlugin` or protect `/admin` another way.

Plugin on/off state moved from the cache to `storage/tardis/plugins.json`; switches stored in the cache are not migrated (a plugin you had disabled is enabled again until you disable it once more). Authentication and authorization plugins cannot be disabled.

## BREAD

| Was | Now |
|---|---|
| `Tardis\Bread\FieldType` enum | `FormfieldManager` registry: `types()`, `has()`, `normalize()`, `assertRegistered()`. `registerType()` makes a type usable in BREAD definitions straight away |
| `ConfigBreadSource` (read/write PHP config) | Removed. `config/bread/*.php` is read-only through `Bread\Legacy\LegacyConfigReader`; import it with `tardis:bread:migrate` |
| `/{slug}`, `/{slug}/{id}` wildcard routes | Routes generated from the definitions and constrained to existing slugs (`Tardis\Http\BreadRoutes`). Names are unchanged (`tardis.bread.index` + `slug`) |
| a BREAD slug such as `users`, `settings`, `bread` | Reserved slugs (`Bread\ReservedSlugs`) cannot be saved or routed; rename the BREAD |
| `Events\BreadCreated/BreadUpdated/BreadDeleted` (barely dispatched) | `BreadRecordCreated/Updated/Deleted` from the create, edit and delete pages; `BreadSaved`/`BreadRemoved` for definitions |
| permissions created inside `BreadManager::save()` | `ProvisionBreadPermissions` listener on `BreadSaved` |
| nothing wrote the activity log | `LogBreadActivity` listener; `tardis.activity_log.enabled` / `log_events` now apply; passwords and hidden attributes are never stored |

New optional definition keys: `components` (replace the Livewire component behind `browse|add|edit|read`), `policy` (the word abilities are built from, default the slug) and `scope` (a model scope applied to listings and every record lookup).

### BREAD routes

BREAD routes are registered from the definitions when routes load. With `route:cache`, a BREAD created afterwards is not routable until you run `php artisan route:cache` again.

## Authentication

`AuthenticationPlugin::authenticate(Request): Request` is replaced by `attempt(array $credentials, bool $remember = false): bool`. The login form and the middleware go through `PluginManager::authenticationPlugin()`, which returns the plugin registered **last**, so a host plugin overrides the built-in one.

## Policies

`BasePolicy` now answers through `BreadAuthorization`, the same check the BREAD pages use. Abilities are `browse posts`, not `browse PostPolicy`; the slug comes from the class (`PostPolicy` → `posts`, `BlogPostPolicy` → `blog_posts`) or from `protected ?string $slug`. Without an authorization plugin a policy allows, like the pages.

## Themes and assets

- `ThemePlugin::getStyles()` is removed. Return CSS custom properties from `getTheme()` (`['--color-primary' => 'oklch(…)']`); Tardis validates them and writes the `:root` rule.
- New: `Tardis::addCss()` / `Tardis::addJs()` and `Tardis\Assets\Asset` (url or inline, optional `integrity`/`defer`).

## Configuration

Removed because nothing read them: `tardis.admin.middleware`, `tardis.plugins.*`, `tardis.media.*`, `tardis.bread.soft_deletes`, `tardis.bread.timestamps`. New: `tardis.authorization.enabled`, `tardis.database.hidden_tables`, `tardis.assets.css|js`.

## Plugins you generated with `tardis:make-plugin`

Plugins generated by earlier development builds did not load: they imported `Tardis\Core\…` classes and required a package that does not exist. Regenerate, or change the imports to `Tardis\Contracts\…` / `Tardis\Manager\…`, require `yellow-three/tardis: ^0.1`, and call `$plugins->enableByDefault('your-plugin')` after `register()`.

## Tooling

`composer lint` ignores `research/`. `tests/TestCase.php` isolates storage per test; a test that saves a BREAD definition and then requests a URL should call `reloadAdminRoutes()` (`tests/Pest.php`).

## Theme and language changes

| Was | Now |
|---|---|
| `vite-plugins/themes-manifest.js`, `config/tardis-themes.php`, the `tardis-themes-assets` publish tag | Removed. Built-in themes live in `Tardis\Theme\BuiltinThemes` and must be declared in your compiled CSS (`@plugin "daisyui" { themes: false; }` plus the `tardis-light`/`tardis-dark` blocks) |
| `AssetManager::availableThemes()` | `ThemeManager::all()` / `find()` / `names()` |
| inline Alpine theme store in the admin layout | `window.Tardis.theme` from the core script; run `npm run build` to refresh `resources/compiled/` |
| hard-coded English strings | `tardis::` translations. Publish `tardis-lang` to override; `#[Title]` attributes now hold translation keys |

## Formfield views

| Was | Now |
|---|---|
| `Formfield::viewData()` overridden by subclasses with `array_merge(parent::viewData(), …)` | Override `extraViewData()`; `viewData(array $context = [])` adds `model` (the Livewire path, `form.<name>` by default), `id` and `extraAttributes` (was `attributes`) |
| field views bound `wire:model="<name>"` and drew their own label | A field view renders **only the control** bound to `$model`; label, help text, error and per-locale repetition come from `x-tardis::form-field`. `BelongsToManyField`/`HasManyField` expose the related class as `relatedModel` (was `model`) |
| options of radio/checkbox and slider limits ignored by BREAD pages | `Formfield::$configurable` maps definition keys onto properties |

## BREAD actions

`Tardis\Bread\Action` was unused and changed shape: it now works on one record (`handle(Model $record, string $slug)`, bulk runs loop over the selected rows) and is registered with `Tardis::addAction()`. `method`, `route` and `download` are gone. The `BREAD index` component's `executionMs`/`warnings` public properties became computed; the warning texts are translated.

## Provider\CSS / Provider\JS

The return type is now `string|Asset|array`. A plugin that returns a string keeps working; implementations that declare `: string` stay valid. `@tardisStyles`/`@tardisScripts` take an optional scope (`@tardisStyles('auth')`) and `AssetManager::styles()/scripts()` take it as an argument (default `admin`).

## New abilities

`manage menus` (existing, now gates the menu builder), `manage dashboard` and `manage appearance` are new fixed abilities. A user who is not a super admin needs them granted on a role (re-run `php artisan db:seed --class="Tardis\\Database\\Seeders\\PermissionSeeder"` to create the rows). `MenuManager::all()` and `WidgetManager::all()` take an optional `$withHidden` argument; `Widget::$component` is now a Blade view name (`tardis::widgets.users`) instead of an unused label.

Three more ship with the system tooling below: `view system` (diagnostics), `view logs` (log viewer) and `run commands` (command runner). They are separate abilities on purpose — one per screen — and each needs to be granted on the role.

## Installation and system tooling

Two new artisan commands ship with 0.1:

- `php artisan tardis:install` — idempotent installer: migrate, seed permissions, publish assets and optionally create the first admin (`--email`, `--force`). Safe to re-run; nothing is overwritten unless you pass `--force`.
- `php artisan tardis:doctor` — install health report covering PHP and Laravel versions, storage permissions, `tardis_*` tables, published assets, route cache, the authorization plugin, the theme manifest, installed plugins and BREAD definitions. Prints a table by default, `--json` for scripts, and exits non-zero when a check fails so it can gate a deploy.

Three screens ship alongside them: **System diagnostics** (`view system`), a read-only **log viewer** (`view logs`) and an **allowlisted command runner** (`run commands`). They are three separate sidebar entries rather than one collapsible group, so revoking one ability never hides or strands the other two.

The log viewer only reads files under `tardis.system.logs.path` (default `storage/logs`) whose name matches `filename_pattern`, and caps a single read at `max_bytes`. It seeks to the end of the file rather than loading it, so opening a multi-gigabyte log costs a seek, not a full read.

The command runner is **disabled by default**, and turning it on is not enough on its own: a command runs only when the app environment is listed in `tardis.system.commands.environments` (default `local`) *and* the command appears in `tardis.system.commands.allowlist` together with the arguments it may receive. An empty allowlist allows nothing.

```php
'commands' => [
    'enabled' => true,
    'environments' => ['local'],
    'allowlist' => [
        'cache:clear' => [],
        'queue:work' => ['--once', '--queue=default'],
    ],
],
```

Allowed entries are options only (`--flag` or `--option=value`); positional arguments are not supported.

There is no arbitrary command execution: the allowlist is checked again at submit time, not trusted from the form. Every attempt is written to the activity log (`tardis.command`, action `executed` or `denied`, with the command, its options and the exit code), refused ones included, unless `tardis.activity_log.enabled` is false.

## Translatable fields: validation now looks at every locale

A translatable field holds one value per locale, and its rules (including `required`) are now applied to **each locale**. Before, `required` only asked whether the array was non-empty, so a record with one language filled in passed. After upgrading, a record that has a `required` translatable field with an empty locale cannot be saved until that locale is filled in.

To keep the old, looser behaviour set `tardis.translation.validation` to `'active'` (only the locale being edited is validated), or set `"validation_mode": "active"` on a single field of a BREAD definition. Other changes from the same release: the create and edit forms show locales as tabs (`tardis.translation.tabs`, default on); BREAD names, descriptions, field labels and menu titles may be a locale map (`{"en": "Posts", "tr": "Yazılar"}`) or a translation key, and plain strings keep working.

## Faz 9 (security fixes) — behaviour that changed

- **Database Explorer is read-only outside `local` and `testing`.** Set `tardis.database.schema_changes.environments` (or `enabled`) in a published `config/tardis.php` to change that. Editing a column the editor cannot describe exactly (for example `tinyint(1)`, an enum, a primary key or an `unsigned` column) is now refused; rename it in the explorer or change it with a migration.
- **Users and Roles screens** can no longer grant more than the acting user holds, and only a super administrator can give or remove the super-admin role. Grant `super-admin` with `php artisan tardis:admin` if nobody holds it.
- **Media**: a rename to an extension outside `tardis-media.allowed_mimes` is refused, and an extensionless upload needs an empty `allowed_mimes`. A filename template that ends in another extension now keeps the uploaded one (`{name}.php` stores `photo.php.png`).
- **BREAD definitions** whose `model` exists but is not an Eloquent model can no longer be saved, and their pages answer 404.
- **Password reset**: the "link sent" message is the same for every address (`tardis::auth.reset_link_sent` changed); a published `lang/vendor/tardis` copy should take the new text and the new `reset_link_invalid` key.
- **Routes**: `tardis.logout` is no longer inside the `tardis.admin` group, and a new `tardis.home` route answers `/admin`.

## Faz 10 — `AuthenticationPlugin` contract

- `loginComponent()`, `forgotPassword()` and `forgotPasswordView()` are removed from `Tardis\Contracts\Plugins\AuthenticationPlugin`: nothing in the package ever called them. Delete them from your plugin (keeping them is harmless).
- `guard()`, `nameField()` and `avatar()` are now used: the default plugin reads, signs in and signs out through its guard, and the sidebar/header show the user through the plugin (`Tardis\Support\PanelUser`). An avatar must be an http(s) or root-relative URL.
- `activity_logs.model_id` is a string column now (migration `2026_11_17_000001_allow_string_keys_in_activity_logs`), so run `php artisan migrate`.
- `activity_logs` gains `ip_address`, `user_agent` and indexes on `created_at` and `user_id` (migration `2026_11_17_000002_add_request_details_to_activity_logs`). Sign-in, failed sign-in, sign-out, role permission changes, user role changes and plugin switches are now logged as well (`model_type` `tardis.auth`, `tardis.role`, `tardis.user_roles`, `tardis.plugin`).

## Faz 10b — themes

- **`ThemePlugin::getTheme()` is replaced by `themes(): array`.** A theme plugin now returns whole theme definitions (the same shape as a `themes.json` entry: `name`, `scheme`, `label`, `colors`, optional `shape`), which appear in the theme picker. The old method wrote an unlayered `:root{…}` rule that overrode every theme, dark mode included; to override individual variables on purpose, ship a stylesheet through `Provider\CSS`.
- **Built-in themes are no longer in the compiled stylesheet.** They are defined once in `Tardis\Theme\BuiltinThemes` and written at runtime with the other themes. (Assets are no longer published; see *Core assets from the package* below.)
- **Themes now set DaisyUI's shape variables** (`--radius-*`, `--size-*`, `--border`, `--depth`, `--noise`), which were never set before; corners and borders of components render with DaisyUI's defaults. A theme may change them with `shape`.

## Faz 10c — service provider and facade

- `Tardis\TardisPluginManagerServiceProvider` and `Tardis\TardisMediaServiceProvider` are gone; their work (views, media config, migrations, `MediaManager`) is in `TardisServiceProvider`. Remove them if you registered them yourself.
- The facade gains `themes()`, `assets()`, `actions()` and `media()`. `Tardis::version()` reports Composer's version for a tagged install.
- Settings: without `storage/tardis/settings/settings.json` the shipped preset is used as the starting point and the file is written on the first save; it is no longer created on the first web request. The CLI now sees the same defaults as the web.
- After updating the package run `php artisan tardis:install --force` (or at least `php artisan view:clear`): Livewire's compiled copies of the panel components are renewed by file time and can outlive an update. The asset directives now compile to `app('tardis.assets')`; clear compiled views once after upgrading.

## Faz 10c — Livewire structure and panel routes

- Livewire components moved to `resources/views/livewire/`; their names are unchanged (`tardis::pages.*`) except the media picker, which is a child component and is now `tardis::components.media-picker` (was `tardis::pages.media-picker`). The database and system home screens moved to `index/` directories; their names (`tardis::pages.database`, `tardis::pages.system`) did not change.
- `vendor:publish --tag=tardis-views` publishes `layouts`, `components`, `formfields`, `widgets` and `partials` only. Published Livewire pages were never used (Livewire reads them from the package); delete `resources/views/vendor/tardis/pages` if you have it, and replace a BREAD screen through the definition's `components`.
- The unused `stats-media` component is removed.
- The UI components page follows the `admin.ui-components` setting: with `hide` the menu item disappears and `/admin/ui-components` answers 404.
- `/admin/media/browse` redirects to `/admin/media`; the `tardis.media.browse` name still exists.
- Plugin routes register before the BREAD routes. A BREAD whose slug equals a plugin route's first segment gets no routes, and such a slug can no longer be saved.
- If you open your own panel route group, use `Tardis\Http\PanelRoutes::panel(fn () => …)` instead of repeating the prefix, name and middleware.
- For files over 12 MB, raise Livewire's `temporary_file_upload.rules` as well as `tardis-media.max_file_size` (README → Media uploads).

## Faz 10c — config root, table name, spelling (0.2)

- `config('tardis-media.*')` → `config('tardis.media.*')` and `config('tardis-icons.*')` → `config('tardis.icons.*')`. Both are sections of `config/tardis.php`, published with `--tag=tardis-config`; the `tardis-media-config` and `tardis-icons-config` tags are gone. A published `config/tardis-media.php` or `config/tardis-icons.php` is still applied over the new keys until 0.3 (with a deprecation notice): move its keys into `config/tardis.php` and delete it. If you published an older `config/tardis.php`, add the `media` and `icons` sections from the package file.
- `php artisan migrate` renames the `activity_logs` table to `tardis_activity_logs` (rows are kept). Update raw queries against the old name; `Tardis\Models\ActivityLog::TABLE` holds the new one.
- Text uses the spelling "Tardis" (was "TARDIS" in places). If you published the translation files, update `shell.name`, `shell.admin` and `shell.footer`. The stored `admin.title` setting keeps whatever value you saved.

## Faz 11 — relation fields

- BREAD definitions no longer have a `relationships` key; it is ignored when read and dropped on the next save. It never affected the forms. Add the relation as a field instead (`belongs_to`, `has_one`, `belongs_to_many`, `has_many`), or use the builder's Relationships tab.
- A foreign key shown as a `number` or `select` field can become `belongs_to` with `model` and `label_column`.

## Faz 11 — image field

- `image` is now its own field type instead of an alias of `file`. Stored definitions are unaffected: saving used to write `file`, so change a field to `image` yourself to get resizing and thumbnails. The builder now detects image columns (`avatar`, `photo`, …) as `image`.
- Run `php artisan migrate` to add `tardis_media.thumbnail_path`. Until then uploads work without thumbnails. Images uploaded before the upgrade keep showing the original in the media grid.
- Install PHP's GD extension to enable processing.

## Faz 11 — front-end helpers

- Tardis now defines `tardis_setting()` and `tardis_menu()`, and, when your application has not defined them already, `setting()` and `menu()`. The short names are declared when the service provider registers, after Composer has loaded your own helper files, so a function of yours with the same name keeps working.

## Faz 11 — users and profile

- The user menu's Profile link now opens the panel's own `/admin/profile` page; a host `profile.edit` route is no longer linked. Add a custom user-menu item if you want your own profile screen there.
- If your user table names its columns differently, set `tardis.users.columns` (`name`, `email`, `password`).

## Faz 13 — no foreign keys to users

- `php artisan migrate` drops the foreign keys from `tardis_role_user.user_id` and `tardis_activity_logs.user_id` to `users.id`. The panel's user model may live in another table, and the keys broke installs and test runs where `users` was not there yet. The columns keep an index. Deleting a user outside the Users screen no longer removes their role links automatically; delete them from `tardis_role_user` in your own code if you need to.

## Core assets from the package

- The panel's `app.css` / `app.js` are served from the package through the hashed `/{prefix}/_assets/…` route; `vendor:publish --tag=tardis-assets` is gone and `tardis:install` no longer publishes. Delete `public/vendor/tardis` (`tardis:doctor` warns while it exists).
- A published layout should replace `<x-tardis::theme-boot />`, `@tardisStyles` and `@livewireStyles` with `<x-tardis::head :theme="$tardisTheme" />` (`scope="auth"` on the login layout), and `@tardisScripts` / `@livewireScripts` with `<x-tardis::scripts />`. The old directives still work.
- The page data is a JSON block (`<script type="application/json" id="tardis-boot">`). The core script still sets `window.__TARDIS__`, but a script that ran before it must read the block instead.

## Media

- `svg` is no longer in the default `tardis.media.allowed_mimes`. A published config keeps its own list; remove `svg` there too unless every uploader is trusted (an SVG can carry script).
- New `tardis.media.per_page` (60): the media screen and picker show one page of a folder. `$files` on those components holds that page only; `$totalFiles` is the count over all pages.

## BREAD pages

- `$bread` on the BREAD pages is a computed property now (`$this->bread`), not public state: a replaced screen that extended one of them, or a test that read `bread` from the snapshot or set `bread.*`, reads `$this->bread` or the definition from `BreadManager` instead.

## User key columns

- `php artisan migrate` gives the user columns of `tardis_role_user`, `tardis_activity_logs` and `tardis_media` the type of your users table key. On an integer-keyed app nothing changes. With UUID or ULID users, tables that already hold rows of the old (unusable) type are left alone; `php artisan tardis:user-keys --force` empties and converts them. Set `TARDIS_USER_KEY_TYPE` when `auto` cannot tell from the model.

## Activity log retention (R50)

- New `tardis.activity_log.retention_days` (365). Nothing is removed until you run or schedule `php artisan tardis:activity:prune`; a published config without the key keeps everything. Add `Schedule::command('tardis:activity:prune')->daily();` to `routes/console.php` to keep the table bounded.
- Settings, permissions, media and BREAD definition changes now add rows to `tardis_activity_logs`. A test that counted every row may need to filter by `model_type`.

## State store driver (R51)

- `php artisan migrate` adds the `tardis_state` table. Nothing changes until you set `TARDIS_STATE_DRIVER=database` (`tardis.state.driver`); then run `php artisan tardis:state:copy --to=database` once, from a server that has the current `storage/tardis`, so settings, menus, plugin switches and BREAD definitions come along.
- Code that read or wrote `storage/tardis/*.json` directly should go through the managers (`Tardis::settings()`, `PluginManager`, `BreadManager`, …) or the `Tardis\State\StateStore` binding; with the database driver those files are no longer written.

## Database screen and migrations (R52)

- The Database screen now writes a migration for every change and runs it, instead of altering the schema directly. Commit the files it writes to `database/migrations`. Set `TARDIS_DATABASE_MIGRATIONS=off` to keep the old behaviour, or `write` to review the files before running `php artisan migrate`.
- The web server user needs write access to `database/migrations` where schema changes are allowed (local by default).

## JSON API (R53)

- Off by default. To use it, set `TARDIS_API=true`, install `laravel/sanctum` (or change `tardis.api.middleware` to your own guard) and give API users "access admin" plus the BREAD abilities they need, as for the panel.

## Panel experience (R54)

- Run `php artisan migrate` for `tardis_notifications`.
- The dashboard has a new `activity-chart` widget; a saved layout puts it at its default place (order 45). A test that listed the default widget ids needs it added.
- Published views: the package's views now use logical utilities (`ms-`/`me-`, `ps-`/`pe-`, `start-`/`end-`, `text-start`/`text-end`) instead of left/right ones, so they mirror in RTL. Re-publish or apply the same change to your copies if you want right-to-left support.

## List actions (R55)

- Every BREAD now has a `duplicate` action next to delete/restore. Remove it per slug with `Tardis::manipulateActions($slug, fn ($actions) => $actions->forget('duplicate'))`. A test that listed the stock action names needs `duplicate` first.
- `Tardis\Bread\Action::redirectTo($record, $slug)` lets an action open a page instead of running `handle()`.
